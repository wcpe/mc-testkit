# 信息脱敏（防内部信息泄露）

> 本仓库是**公开仓库**：代码、文档、提交信息、PR 描述、Issue、CI 日志都会永久公开，且 PR 描述会被
> GitHub 自动抓取进 Release 正文（见 `docs/CONTRIBUTING.md` §8.1）。**任何进入这些面的内容都按永久公开对待。**
>
> 本规则约束人类协作者与 AI 代理的一切产出。

## 1. 禁止出现的内部信息

以下内容**一律不得**写入代码、注释、文档、测试数据、提交信息、PR / Issue 描述、CI 配置或截图：

| 类别 | 具体禁止项 | 举例（反面） |
|---|---|---|
| 主机标识 | 内网主机名、机器编号、节点名、集群代号 | `9102`、`build-node-3`、`prod-db-01` |
| 网络标识 | 内网 / 公网 IP、内网域名、非公开端口 | `10.0.3.15`、`*.internal.corp` |
| 绝对路径 | 含用户名的本机路径（`/home/<用户>`、`/Users/<用户>`、`C:\Users\<用户>`）、任何开发机目录结构 | `/home/alice/projects/foo` |
| 凭据 | 真实密码、token、API key、私钥、数据库连接串、cookie | `password=Hunter2`、`BEGIN PRIVATE KEY` |
| 消费方身份 | 真实消费方项目名、组织名、产品名、内部代号 | 具体接入方的项目代号 |
| 真实数据 | 真实玩家名 / 昵称、真实 UUID、真实账号、真实服务器世界名 | 真实玩家 ID、真实存档名 |
| 运行画像 | 能反推生产环境的运行数据：真实负载量、真实机器配置、业务指标 | 「某服日常 800 在线」这类描述 |
| 环境细节 | 未公开的 JDK / OS / 依赖版本组合、内部镜像地址 | 内部 Nexus 地址 |

## 2. 允许出现的公开信息

- 本项目的公开坐标：`top.wcpe.mc-testkit`、`maven.wcpe.top`、仓库 URL。
- 上游公开依赖与官方地址：PaperMC API、SpigotMC Jenkins、Gradle、Mojang 等。
- MC 平台名与公开版本号（`1.20.1`、`Paper`、`Velocity`）。
- **占位 / 哨兵值**：`s1`、`test-bot`、`example.com`、`127.0.0.1`、`secret: sentinel`。
- 已脱敏的相对量级：把主机编号换成「验收机」「一台 Linux 环境」，把消费方名换成「消费方」。

## 3. 改怎么写（脱敏替换表）

| 想表达 | 写这个 |
|---|---|
| 某台内网机器 | 验收机 / 一台 Linux 环境 / CI 环境 |
| 某个消费方项目 | 消费方 / 接入方 / 首个消费者 |
| 某次真实运行数据 | 「实测约 N MB/分钟」并可保留量级，需去掉主机与项目标识 |
| 本机路径 | `<工程目录>` / `$PROJECT_DIR` / 相对路径 |
| 真实账号与密码 | `example-user` / `$SECRET` / 从环境变量读取 |

**判据**：这条信息贴到公开 issue 里，作者会不会不舒服？会 → 就脱敏。

## 4. 测试与日志的额外要求

- 测试固定夹具一律用占位值，禁止贴真实环境抓包 / 真实日志片段。
- 若确需保留真实数据用于回归，**先脱敏再入库**：替换主机、路径、账号，只保留能复现缺陷的结构。
- 运行期产物（`build/`、`run/`、`results/`、`*.log`、`*.pid`、`process-ledger.properties`）**一律不入库**，见 `.gitignore`。
  其中 `process-ledger.properties` 含进程完整命令行，排查时若需贴出，先删掉命令行与参数行。
- `guard.evidence` 之类导出的证据文件只落本地临时目录，不提交。

## 5. 提交前自检

写代码、发提交、开 PR 前逐条过：

- [ ] 没有内网主机名 / 机器编号 / IP / 内网域名
- [ ] 没有含用户名的绝对路径
- [ ] 没有真实凭据（含测试里硬编码的「像真的」密钥）
- [ ] 没有消费方项目名 / 组织名 / 真实玩家与账号
- [ ] 没有可反推生产环境的运行画像
- [ ] 提交信息与 PR 描述同样适用（它们会永久公开并被 Release 抓取）
- [ ] 日志与证据文件的片段已脱敏

## 6. 发现已泄露

1. **立即停止扩散**：不再在公开面复述该信息。
2. 凭据类：**先轮换凭据**，再清理（见 `SECURITY.md`）。
3. 非凭据类：改写对应的代码 / 文档 / PR 描述，必要时清理历史（历史改写须经维护者确认，
   已发布 tag 对应的提交不改写）。
4. 记一条 `CHANGELOG` 修复说明（不写具体泄露内容）。
