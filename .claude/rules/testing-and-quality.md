# 验证门与质量底线（防质量漂移）

> 项目特定的测试与质量要求。通用反模式禁令（上帝类、长方法、复制粘贴、魔法值、吞异常、资源泄露、循环依赖、静态可变单例等）仍然适用。

## 1. 验证门（权威判据）
- **每个变更必须过验证门才算完成**，判据以**入库真源**为准：① `docs/PRD.md` 验收标准对应项满足；② 本文 §2 高风险区相关测试通过；③ 受影响组件全部测试绿（按本项目实际测试 / 构建命令执行，见 `docs/OPERATIONS.md`）。
- **完成以证据为准、不轻信报告**：声称"做完 / 修好 / 通过"前，必须出示客观证据（命令 + 关键输出、失败用例从红转绿、有实机 / 集成维度的附该维度复验结果）。拿不齐 = 未完成、继续做。
- **被推翻就回流继续修**：声称完成后被实测 / 实机 / 用户验收推翻，即视为未完成，回到对应技能的验证步骤继续修，不另开流程、不重标状态。
- **提交受验证门门控**：验证门未全绿不得 `git commit`（见 `git-commit.md` §3）。
- `.tmp/` 下实施计划的里程碑勾选仅作开发期辅助，不入库、不作权威判据。
- **禁止**以注释、跳过、删除失败测试的方式让测试"通过"。
- 改功能代码前先跑相关测试确保通过；新增 / 改逻辑同步加测试。

### 1.1 测试分层（怎么分、在哪跑）
- **单元**：纯逻辑（拓扑模型解析、配置文本生成、端口/版本推导等纯函数）—— 不连外部依赖，最快最多。
- **集成**：用 Gradle TestKit 驱动插件，验证任务注册、配置期校验、任务图（无环 / 命名稳定 / 缺依赖报错）。
- **E2E**：本工具"自举"——以首个接入项目（或 `template/` 示例）为消费者，拉起真实「代理 + 后端」跑通场景（见 PRD 验收，含实机维度需用户确认）。
- **何时跑**：单元 / 集成随每次改动（如启用 CI 则随 CI）；E2E 在发版前至少跑一遍。

## 2. 必测的高风险区
- **进程生命周期与收尾**：后台代理 / 集群后端 / 机器人进程，在【正常结束 / 场景失败 / 异常中断】各路径下都必须被收尾杀掉、端口释放、无残留；多服集群须全部回收。
- **时序与就绪**：代理先于后端就绪时机器人重试直到成功；前台被测后端自停应正确驱动后台收尾，不早杀也不漏杀。
- **环境契约**：经代理时机器人协议版本固定为后端版本；BungeeCord 后端三件套（`spigot.yml` / `paper-global.yml` / `online-mode`）写入正确；依赖（数据源 / Redis）注入缺失时明确中文报错而非静默继续。
- **任务图与配置期校验**：任务图无环、任务名稳定、必填缺失 / 路径不存在时报中文明确错误。
- **可移植 / 幂等**：不写死本机绝对路径；运行目录可清理重建；缓存复用不破坏正确性。
- **跨平台**：Windows / Linux 下子进程启动、pid 收尾、可执行名（`node`/`npm`）差异。

## 3. 质量底线
通用反模式底线（任何项目都适用）：
- 分层依赖单向、不反向穿透（编排助手不反依赖消费项目 / `template/`）。
- 锁 / 临界区职责单一、不嵌套；子进程等待不要持锁，高开销 IO 在锁外。
- 核心计算尽量做成无副作用纯函数（拓扑解析、配置生成），便于穷举测试。
- 中文分级日志（ERROR/WARN/INFO/DEBUG），不留 `println` / `console.log` 等临时调试输出。
- 不硬编码凭据 / 端口 / 超时 / 绝对路径，走配置或常量（可移植是硬指标）。
- 结果判定只认结果文件，不靠"日志里好像成功了"猜测。
