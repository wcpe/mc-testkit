# ADR-0001：以 Gradle 插件形态构建，自实现服务端/代理的下载与运行

## 状态
已接受

## 背景
mc-testkit 要编排真实 MC「代理 + 后端」拓扑跑 E2E。第一个能力就是把服务端 / 代理下载下来并运行。消费方都是 Gradle 构建的 JVM 插件，工具以 Gradle 形态接入最自然。下载 / 运行能力有两条路：外挂某个第三方下载 / 运行库，或在插件内自实现。

## 决策
用 **Kotlin + Gradle 插件**（`java-gradle-plugin` + `kotlin-dsl`）实现，**在插件内自实现**服务端 / 代理的下载与运行（Paper/Folia 经 PaperMC 下载 API、BungeeCord 经 SpigotMC Jenkins，带本地缓存与校验、子进程启动），自身在此之上做编排（拓扑、任务装配、机器人驱动、结果判定、收尾、环境契约固化）。插件 id `top.wcpe.mc-testkit`，发布到 maven.wcpe.top。**不外挂任何第三方下载 / 运行库依赖。**

## 理由
- **自含、可移植**：不外挂第三方下载库，CI / 他人拉下即用、不受外部库版本联动与发布渠道影响；离线 / 弱网可经缓存或环境变量覆盖兜底（NFR）。
- **平台覆盖可控**：目标平台（Paper/Folia 后端 + Velocity/Waterfall/BungeeCord 代理）由内置模块直接覆盖——外部下载库未必齐全（如 BungeeCord 常缺「下载即跑」支持）。
- **Gradle 形态**让消费方 `plugins { }` 一行接入，与现有 JVM 构建无缝；Kotlin DSL 适合声明式拓扑配置，与被测插件同语言、维护门槛低。
- 下载 / 运行模块**保持精简**：只覆盖目标平台的 jar 解析 + 缓存 + 启动，不搬运插件市场下载等非必需能力（见 `ARCHITECTURE.md`「简单优先」）。

## 后果
- 下载 / 运行由本插件内置模块负责、需自行维护（换平台 / 改下载渠道时同步）；不依赖外部库的演进与可用性。
- 运行需 Gradle + JDK 环境；首次运行需网络下载服务端 / 代理（或预置缓存 / 环境变量覆盖）。
- 平台范围见 [ADR-0003](0003-p1-platform-scope.md)；编排模型见 [ADR-0004](0004-orchestration-model.md)。

## 备选方案
- **外挂第三方下载 / 运行库**：少写代码，但承担外部库的版本联动 / 发布渠道 / 平台覆盖缺口（如 BungeeCord）与可用性风险，且耦合个人制品的发布负担，落选。
- **纯脚本（shell/Make）编排**：跨平台差、与 Gradle 生态割裂、难复用，落选。
- **容器编排（docker-compose）跑服务端**：MC 服务端容器化与版本下载仍需自管，且偏离消费方的 Gradle 构建上下文，落选。
