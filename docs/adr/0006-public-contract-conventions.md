# ADR-0006：对外契约命名约定（env 前缀 / 任务命名 / 控制协议 / 结果文件）

## 状态
已接受

## 背景
第一期多个 FR（FR-02~07）要并行开发，它们共同依赖一套对外契约：环境变量前缀与名集、自动生成任务的命名、机器人↔桩控制协议、桩写出的结果文件约定。若不先冻结，多线并行会在这些共享约定上反复返工与冲突。其中环境变量前缀此前是开放问题——是沿用某项目专属前缀（如 `XXX_E2E_`）风格，还是统一一个工具级前缀。详细契约 spec 落在 `docs/API.md`，本 ADR 只记**决策与理由**（避免与 API.md 双源）。

## 决策
冻结以下对外命名约定（语义详见 `docs/API.md`）：

- **环境变量前缀** `MC_TESTKIT_E2E_`，**固定、不做 DSL 可配**（本期单一消费者，按 YAGNI）。
- **任务命名约定**（由场景/代理名折 PascalCase 派生，不显式登记）：`prepareE2e<Key>`、`e2e<Key>`、`e2e<Key>Via<Proxy>`、`launch<Key>Bot`、`e2e<Key>WithBot`，及固定名 `npmInstallE2eBot` / `syncE2eRuntimeCache` / `purgeE2eRuntimeCache`。
- **机器人↔桩控制协议**消息名 `E2E_READY` / `E2E_STRESS_RESULT` / `E2E_DISCONNECT_NOW` / `E2E_UI_TOKEN`（载荷走 `:` 后缀）。
- **结果文件**：`<scenario>.properties`，键 `status`(PASS/FAIL) / `message`；判定**只认结果文件**（架构不变量真源）。

## 理由
- 统一工具级前缀 `MC_TESTKIT_E2E_` 与工具"通用、跨项目复用"的定位一致，且避免与消费方其它环境变量撞名；项目专属前缀只适合单项目。
- 任务名 / 控制协议 / 结果文件沿用首个接入项目已跑通的既证约定，降低其迁移成本与认知负担。
- 任务名采用**纯约定派生**而非显式登记：本项目是新建、无历史不规则任务名包袱（相比有历史包袱、需显式登记任务名的项目，这里是一处简化）。
- 固定不可配 = 简单优先；真出现"多消费者在同一 CI 撞前缀"的实需，再加 DSL 可配前缀（不为未来预留空壳）。

## 后果
- 契约一经发布即稳定；破坏性变更（改前缀 / 任务名 / 协议 / 结果键）按 SemVer 升 major 并在 CHANGELOG 写迁移。
- Wave 1 各 FR 可安全并行引用 `contract/` 常量，不必各自再定。
- 环境变量**全集**随 FR-02/04/06 实现补全，但前缀与命名风格不变；补充项也走 `docs/API.md` 更新。

## 备选方案
- **沿用项目专属前缀（某项目私有 `XXX_E2E_` 风格）**：与工具通用定位不符，迁移到第二个消费者即需改名，落选。
- **DSL 可配前缀（`mcTestkit { envPrefix = ... }`）**：当前单一消费者无此需，属为未来预留空壳，YAGNI 落选（留待真实冲突出现）。
- **任务名显式登记**：可保住历史不规则名，但本项目新建无历史包袱，纯约定派生更简单，落选。
