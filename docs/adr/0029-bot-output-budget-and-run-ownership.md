# ADR-0029：机器人与钩子进程的输出字节预算，及结果目录的输出所有权

## 状态
已接受

## 背景
- bot 与场景钩子后台进程的输出原先用 `ProcessBuilder.Redirect.appendTo(File)` 交给内核直接写文件：JVM 不经手，既没法计数、限流，也没法在越限时中断。一次本地事故里 9 个 bot 日志合计写到 130 GiB，直到磁盘写满才停。
- 后台进程收尾此前只靠 pid 文件与停任务。构建结束时仍在跑的进程、根进程退出后仍握着输出管道的子孙进程，都可能在构建之外继续写结果目录。
- 结果目录跨构建复用。上一次构建若没收尾（被强杀、被外部超时杀掉），它的进程可能还在写，本次构建照常接手就会和它并发写同一目录。
- 初版用「上一次不是 `CLOSED_OK` 就拒绝接手」防范这一点。实测连跑矩阵时，一格失败让后面所有格都在准备阶段被拒：已经收尾干净的失败也被当成了隐患。

## 决策
1. **管道 + 有界泵**：bot 与钩子后台进程的 stdout / stderr 合流走管道，由插件内的泵线程按预算写日志文件。预算分「单个日志文件」（默认 8 MiB）与「整个构建」（默认 128 MiB）两级按字节计数，可调、上限 1 GiB。越限即在日志末尾写一行 `[OUTPUT_LIMIT]`，结束本次构建监管的全部进程并判失败。
2. **构建级共享服务持有预算与监管**：每个顶层构建一份 `RunOutputService`（Gradle BuildService，配置缓存复用时也是新的一份），所有任务共用同一预算。监管器只认本构建自己起的进程及其观察到的子孙进程（按 pid + 启动时刻识别，防 pid 复用），负责监管期限（由场景结果等待上限推出，见 FR-32）、非零退出、管道被子孙进程继承、构建结束仍未收尾等判定。失败是粘性的、先到先得，原因收敛成有界的 ASCII 文本。钩子拿不到预算时拒绝启动外部命令，不退回无上限写盘。
3. **结果目录的输出所有权记录 `output-run.state`**：接手时写 `RUNNING`；收尾时写 `CLOSED_OK` / `RUN_FAIL`、计入预算的字节数、失败原因，以及收尾期限到时仍存活的受监管进程（`live=`，无法确认时为 `live=unknown`）。下一次构建**只在上一次可能仍有进程在写时拒绝接手**：停在 `RUNNING`、`live=unknown`、没有 `live=` 记录的旧格式、所列进程仍存活、或记录读不懂。上一次失败但其进程都已确认结束时，只告警、照常接手。拒绝时不改写记录。

## 理由
- 只有经 JVM 手的输出才能计数和中断；内核直写下，任何事后清理都晚了。
- 预算放在构建级而不是任务级：一次构建里多个任务、多个进程叠加才是事故形态，各任务各自设上限仍会被乘法放大。
- 所有权以「是否还有进程可能在写」为判据，而不是「上一次是否成功」：上一次的失败已由那次构建自己报告；场景结果文件每次开跑前都会清掉，结果读不到就判失败，不会把上一次的结果当成本次的；真正的隐患只有并发写入。按这个口径，连跑矩阵里的一格失败不再拖垮后续各格，而被中断、收尾不干净的构建仍被挡住。
- 拒绝时保留记录：被拒的构建若改写记录，下一次构建看到的就是「被拒」而不是原隐患，隐患会被洗掉；两个构建同时跑时，后来者也不会冲掉先来者的所有权。
- 存活进程按 pid + 启动时刻记录：下一次构建可以自己确认它们是否已经结束，而不必一律等人工处理。

## 后果
- **破坏性**：单个 bot / 钩子输出超过 8 MiB、或整个构建超过 128 MiB，以前不失败、现在失败；输出量大的消费方需调高上限。
- 被中断的构建会让下一次构建在准备阶段失败，需人工确认进程已结束后删除 `output-run.state`；报错给出文件路径与仍存活的进程。
- `live=` 最多记 64 个进程，超出按无法确认处理；状态文件超过 4 KiB 就不是本插件写的，拒绝接手。
- 服务端日志不在本预算内（仍由服务端进程自己写文件），是已知缺口，另行处理。
- 契约（配置项、失败原因、状态文件格式与接手规则）见 [`API.md`](../API.md) §3.7。

## 备选方案
- **保留 appendTo，构建结束后再查文件大小**：越限时磁盘已经写满，落选。
- **按任务各自计数**：多任务叠加仍可乘法放大，落选。
- **上一次不是 `CLOSED_OK` 就拒绝（初版）**：一格失败连坐后续所有构建，连跑矩阵实测不可用，落选。
- **不记录、每次无条件接手**：被中断构建的残留进程会和本次构建并发写同一目录，落选。
- **按目录加文件锁**：只能防同时运行的两个构建；锁随构建 JVM 退出而释放，防不了「构建已死、子进程还活着」，落选。
